# WHY THERE ARE TWO KEY-EXCHANGE VECTOR FILES
#
#   The Chinese and English editions of GM/T 0044.5-2016 carry DIFFERENT worked
#   examples in Annex B, and both are internally consistent:
#
#     sm9_keyexchange.txt        Chinese edition, hid = 0x02, SK = C5C13A8F...
#     sm9_keyexchange_hid03.txt  English edition, hid = 0x03, SK = 68B20D30...  (this file)
#
#   This is not a contradiction in the algorithm. GM/T 0044.3-2016 defines hid as
#   "identifier of the encryption private key generating function, denoted by one
#   byte", which "the KGC chooses ... and makes public" - it is a deployment
#   parameter, not a fixed per-algorithm constant. The two editions simply chose
#   different hid values when generating their examples. Carrying both exercises
#   the implementation against a KGC-selected hid rather than a hardcoded one.
#
#   Note: two display lines in the English Annex B print the concatenation as
#   "426F6202" / "416C6963 6502" (hid = 0x02) inside an otherwise hid = 0x03
#   example. Those two lines are typos in that edition - the H1 values printed
#   beside them are H1(Bob||0x03) = 9CB1F628... and H1(Alice||0x03) = 32DEE8AA...,
#   and every downstream value is the hid = 0x03 one.
#
